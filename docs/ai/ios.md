# iOS

Verified at: aaf4427f
Covers: `iosApp`, `shared/src/iosMain`, `shared/build.gradle.kts`, `.github/workflows/ios.yml`

The iPhone app in `iosApp/` is native SwiftUI. It uses the KMP `shared` module as the static framework `Shared`, which holds models, use cases and the Supabase data layer. None of the Android Compose UI is reused.

Status: browsing, Google and email sign-in, interactions, profile, settings and submissions on the simulator against `qode-dev`. It has Home (banners, service chips, sort, promocodes), promocode detail, the service search sheet, Feed and post detail. Home and Feed have a + menu (Submit promocode, Create post; signed-out taps open sign-in). The Feed toolbar also has Settings and an account button. Signed out, the account button opens sign-in (Google or an emailed code), and new users then go through the consent step. Signed in, it opens Profile: counts, the user's own promocodes and posts, Blocked users with unblock, and Sign out. Settings has the theme (stored in `@AppStorage("theme")`), Language (opens the app's page in iOS Settings, because iOS sets each app's language there), feedback mail, GitHub, Telegram, Terms, Privacy, the version, and Delete account when signed in (App Store guideline 5.1.1(v)). Promocode and post detail have vote buttons and a "…" menu with Report and Block user (Block is hidden on your own content); signed-out taps open sign-in. Still missing (tracked in the Qode GitHub project, #150, #151 and #173–176): Sign in with Apple, which App Store guideline 4.8 requires because Google sign-in exists; open-source licences, rate app, push notifications, submissions, push, a prod config and App Store release. The plan is in `~/.claude-personal/plans/could-it-port-it-serene-valley.md`.

## How Swift reaches Kotlin

- `shared/src/iosMain/.../ios/QodeApi.kt` is the only API Swift uses. It wraps use cases and turns `Result` into return values or a thrown `QodeException`. It maps models to plain classes (`PromocodeItem`, `PostItem`, ...) because value classes, `Instant` and generic `Result` export badly to Objective-C. Pagination cursors stay inside `QodeApi`. Kotlin `suspend` functions show up in Swift as `async throws`, so SKIE isn't needed.
- `AuthApi.kt` covers email codes, Google ID tokens, consent, sign-out, legal documents and `currentAccount()`. One instance holds one sign-in attempt, because it keeps the new user that is waiting for consent. `currentAccount()` reads the Supabase session directly. `GetAuthStateUseCase` and `ObserveCurrentUserUseCase` share their flows with a replayed value, and `observeUser` emits only once, so they'd return stale state right after sign-in. Swift's `AccountStore` refreshes after every auth action instead of observing.
- `InteractionApi.kt` handles votes (`GetUserInteractionUseCase`, `ToggleVoteUseCase`), reports (`ReportRepository`, the same call Android's report screen makes) and blocks (`BlockUserUseCase`). It reads the user ID from the Supabase session. Swift uses the shared `VoteState` enum and `VoteState.Companion.shared.computeScoreDelta` for the optimistic score. After a report or block, `AccountStore.contentChanged()` bumps `contentVersion`, and Home and Feed reload on that and on account changes.
- `ProfileApi.kt` handles the profile (counts from `users`), own content (`GetPromocodesByUserUseCase`, `GetPostsByUserUseCase`), blocked users, unblock and `DeleteUserAccountUseCase`. Deletion calls the `delete-account` function and clears the session. Navigation inside Feed uses `AppRoute` (`Profile.swift`).
- Submissions run in the foreground. `SubmitApi.kt` calls `SubmitPromocodeUseCase` / `SubmitPostUseCase` directly with a progress callback, inside a `UIApplication` background task. It skips the Enqueue use cases, which need Android's WorkManager scheduler. `ImageAttachment` (`Submit.swift`) scales picked photos to at most 2048 px and writes JPEG temp files, because the buckets allow only JPEG/PNG/WebP up to 5 MB and iPhone photos are often HEIC. `IosStorageRepository` uploads those files through `SupabaseStorageDataSource`. The form is a single screen, not Android's wizard, and validation stays in shared code. Shared code accepts one-letter codes.
- Error messages: `QodeException.errorPath` is the error's name without the package, such as `PromocodeError.SubmissionFailure.DuplicateCode`. The string import script reads Android's `core/ui/.../ErrorStringMapper.kt` and generates `Qode/ErrorKeys.swift`, and `errorMessage()` uses that mapping first.
- The consent step asks for an optional display name, and Profile can rename the user (`ProfileApi.updateDisplayName`). Users without a name show as "Qode user".
- The session is stored by supabase-kt's default settings storage (`NSUserDefaults`), not the Keychain. Move it to the Keychain before an App Store release.
- `KoinIos.kt` (`KoinIosKt.doInitKoin` in Swift) starts Koin with `sharedDataModule`, `domainModule` and an iOS module. That module binds the interfaces Android provides from `core/data`. Only `ReportRepository` exists so far (`IosReportRepository`, `NSUserDefaults`). Use cases that need the others (storage, submission schedulers, device preferences, Google ID token) fail at resolution until they're bound.
- Name clashes: `shared` exports its own `Error` type, so Swift code writes `Swift.Error`. A Kotlin property called `description` becomes `description_`.

## Project

- `iosApp/project.yml` is the XcodeGen spec. `Qode.xcodeproj` and `Info.plist` are generated and gitignored. Run `xcodegen generate` after adding files or changing settings.
- A pre-build phase runs `./gradlew :shared:embedAndSignAppleFrameworkForXcode`, so Xcode builds the Kotlin side too.
- `Config/Debug.xcconfig` holds the `qode-dev` URL and publishable key; both are public. It writes the URL as `https:/$()/…` because xcconfig treats `//` as a comment. Both configurations use it until a prod config exists.
- Google sign-in uses the GoogleSignIn-iOS SDK, added through Swift Package Manager in `project.yml`, with the same nonce scheme as Android: Google gets the SHA-256 hex of a random nonce, Supabase gets the raw nonce. The iOS OAuth client belongs to the Firebase iOS app `qode-ios-debug` in `qode-dev` (`firebase apps:sdkconfig IOS 1:539742119334:ios:a20a09f5945a54878f9b67`). Its ID and reversed URL scheme are in `Debug.xcconfig`, and it's also in Supabase's Google `client_id` list in `supabase/config.toml`. A prod build needs its own iOS client in `qodein` added to `qode-prod`.
- Firebase: Analytics and Crashlytics come from firebase-ios-sdk through Swift Package Manager. `Qode/GoogleService-Info.plist` belongs to the `qode-dev` iOS app; it's public, like Android's `google-services.json`. `Track` (`Analytics.swift`) logs the same event names and parameters as Android's `core/analytics`, and the main screens set `.analyticsScreen(name:)`. A post-build phase uploads dSYMs to Crashlytics, but simulator builds skip it. The simulator log hides individual events, so check them in the console's DebugView by launching with `-FIRAnalyticsDebugEnabled`.
- CI: `.github/workflows/ios.yml` builds the app for the simulator on `macos-26` whenever `iosApp`, `shared` or the Gradle files change. Signing is off.
- Strings: `Qode/Localizable.xcstrings` is generated from the Android `strings.xml` files (en, ru, kk) by `iosApp/scripts/import_android_strings.py`. Add a key to `KEYS` there and rerun it. It also regenerates `ErrorKeys.swift`. Don't edit either file by hand. `core_notifications_upload_progress` has no Kazakh translation, so it falls back to English. Swift reads strings with `L("key")`.

## Commands (from `iosApp/`)

- Generate: `xcodegen generate`
- Build: `xcodebuild -project Qode.xcodeproj -scheme Qode -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build/DerivedData build`
- Run: `xcrun simctl boot "iPhone 17 Pro"; xcrun simctl install booted build/DerivedData/Build/Products/Debug-iphonesimulator/Qode.app; xcrun simctl launch booted com.qodein.qode.debug`
- Another language: add `-AppleLanguages "(kk)"` to `simctl launch`.
- Drive the UI with `maestro test <flow>.yaml`; it works on the simulator. `inputText` needs the field tapped first.
- Photos for submission tests: `xcrun simctl addmedia booted <file.jpg>`. The simulator also has sample photos. After `delete-account`, public image URLs can keep returning 200 from the CDN cache for a while; add a query string to check the origin.
- Google sign-in on the simulator needs a person to type the Google password.
- Test votes, reports and blocks with a throwaway `+alias` account, then delete it with Settings → Delete account or directly through `delete-account` (email code via `/auth/v1/otp` and `/auth/v1/verify`, then `POST /functions/v1/delete-account` with its token). Foreign keys cascade its votes, reports and blocks. Reported IDs also live in the simulator's `NSUserDefaults`, so reported items stay hidden there until the app is reinstalled.
- To test sign-in, use a `+alias` of a Gmail address for a fresh user (it shows the consent step) and read the 6-digit code from the email subject ("Qode code: NNNNNN").
